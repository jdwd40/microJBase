# v0.2 Implementation Plan

This document freezes the sequential v0.2 queue. Each item lists purpose, scope, dependencies, acceptance criteria, and test expectations. One active implementation PR at a time; every implementation PR is built by Kimi, independently reviewed, must have green CI, and merges only after a SHIP verdict with no unresolved BLOCKER/MAJOR.

## V02-04 — Schema-admin connection and capability boundary

**Purpose.** Introduce the schema-admin connection pool and fail-closed capability checks that guard every later admin operation.

**Scope.**

- Unwired, disabled-by-default schema-admin pool abstraction over `SCHEMA_DATABASE_URL`.
- Fail-closed role/capability checks: require a non-superuser, non-`BYPASSRLS` role that owns every table it mutates; reject superuser, `BYPASSRLS`, role-management rights, and unsafe database-wide privilege assumptions. The role may equal the migration role but the connection surface stays distinct and must never be the runtime role.
- Startup fails when exactly one of `SCHEMA_DATABASE_URL` and `MICROJBASE_ADMIN_TOKEN_SHA256` is configured; with neither, the pool is inert.
- Runtime and migration connections remain unchanged.
- No routes.

**Dependencies.** V02-03.

**Acceptance criteria.**

- With neither setting the pool is inert and admin operations cannot run; with exactly one setting startup fails.
- Unsafe role configurations are rejected before any operation executes.

**Test expectations.**

- Unit tests for capability checks against mocked role attributes.
- Integration tests with real PostgreSQL roles covering each rejection case.

## V02-06 — Typed DDL planner/compiler and executor

**Purpose.** Build the single audited DDL compiler and transactional executor that all later mutation commands use.

**Scope.**

- Typed DDL planner/compiler: conservatively validated and quoted identifiers, parameterised values, typed allowlist/template defaults.
- Initial type allowlist: `text`, `integer`, `bigint`, `boolean`, `uuid`, `timestamp`, `timestamptz`, `date`, `numeric`, `jsonb`.
- Initial default templates: a typed literal, `current_timestamp` (emitting `CURRENT_TIMESTAMP` only for `timestamp`/`timestamptz`), and `random_uuid` (emitting `gen_random_uuid()` only for `uuid`).
- Dry-run plans, transactional executor, advisory serialization using the reserved schema-DDL advisory-lock key `7921890504698152930` (distinct from the migration runner key `7921890504698152929`), safe PostgreSQL error mapping.
- No table mutation commands yet.

**Dependencies.** V02-05.

**Acceptance criteria.**

- Only allowlisted types and validated identifiers compile.
- Plans support dry-run without execution.
- Executor maps PostgreSQL errors to safe envelopes without leaking internals.
- Schema-DDL serialization uses the reserved key `7921890504698152930`, distinct from the migration key `7921890504698152929`.

**Test expectations.**

- Compiler unit tests for allowlist enforcement and identifier quoting.
- Executor integration tests with real PostgreSQL, including error mapping.

## V02-09 — Defaults, nullability, and safe type changes

**Purpose.** Manage column defaults, nullability, and a documented safe type-conversion matrix.

**Scope.**

- Typed literal/template defaults; `SET DEFAULT` and `DROP DEFAULT`.
- `SET NOT NULL` / `DROP NOT NULL` with preflight checks.
- Documented safe conversion matrix; no arbitrary `USING` SQL.

**Dependencies.** V02-08.

**Acceptance criteria.**

- Only matrix-approved conversions execute.
- Preflight failures abort safely without partial mutation.

**Frozen conversion matrix (implemented 2026-09-25).** `compileChangeColumnType` executes only the following pairs, each a widening PostgreSQL applies without a `USING` clause and without data loss for any source value. There is deliberately no arbitrary `USING` path.

- `integer` -> `bigint`
- `integer` -> `numeric`
- `bigint` -> `numeric`
- `date` -> `timestamp` (midnight extension; nothing touching `timestamptz` is ever automatic)

Type changes additionally refuse safeguarded columns (generated, identity, primary-key), columns carrying a default (drop the default first), and columns used by a constraint or index.

**Test expectations.**

- Tests covering existing data, failed preconditions, rollback, and unsupported conversions.

v0.1 architecture (implemented)

microJBase v0.1 is one TypeScript application connected to one PostgreSQL database. An optional reverse proxy terminates TLS; it is not part of the application. There are no internal network calls, queues, caches, or independently deployed services. 

Client
  |
  | HTTPS + bearer session
  v
Reverse proxy (optional)
  |
  v
microJBase server (one Node.js process)
  |-- HTTP module
  |-- Auth module
  |-- Data module
  |-- Core module
  `-- PostgreSQL adapters
          |
          v
      PostgreSQL 16+

The API process authenticates a session, begins a database transaction, sets the local PostgreSQL identity (microjbase.user_id), and lets row-level security decide which rows the caller may access. The identity setting is transaction-local so a pooled connection never retains a user’s identity.

Module dependency rules: auth/ and data/ contain domain behaviour and depend on frozen contracts, not PostgreSQL or Fastify; database/ is the only module that imports pg; http/ maps HTTP to service calls and owns transport validation; main.ts is the only composition root. Source: ARCHITECTURE.md.

Privilege lanes (implemented)

v0.1 separates the migration role, which owns objects and performs DDL, from the restricted runtime role, which is non-superuser and non-BYPASSRLS. The server refuses to start when the runtime role violates those checks.

  • DATABASE_URL — restricted runtime data role used by request handlers.
  • MIGRATION_DATABASE_URL — explicit migration command role; never used by request handlers.

v0.2 target shape (planned)

Everything in this section is planned capability from docs/v0.2-architecture.md. None of it is implemented at v0.2 intake. 

HTTP routes (existing /v1/auth, /v1/data)
   |-- Auth service ---- repository contracts ---- PostgreSQL adapters
   |-- Data service ---- repository contracts ---- PostgreSQL adapters
   |-- Core config/errors/logging
   `-- (planned) Admin schema module
          |-- Admin HTTP routes (/v1/admin/schema)
          |-- Schema admin service (typed commands)
          |-- Audited DDL compiler/executor
          |-- Schema introspection readers
          `-- Bounded admin pool (SCHEMA_DATABASE_URL)
  • A third, optional schema-admin lane (SCHEMA_DATABASE_URL) is used only by the disabled-by-default admin/schema module and fails closed on superuser, BYPASSRLS, or role management.
  • Schema operations are typed commands compiled by one audited DDL layer; HTTP handlers never construct SQL; identifiers are conservatively validated and quoted; values stay parameterised; defaults come from a typed allowlist/template model.
  • The v0.2 type allowlist is text, integer, bigint, boolean, uuid, timestamp, timestamptz, date, numeric, jsonb.
  • A durable exposure registry separates “table exists” from “table is exposed to the data API”, with a one-time migration from MICROJBASE_TABLES; after import the environment variable cannot re-expose a table an operator unexposed.
  • RLS management is limited to predefined ownership templates around microjbase.user_id; arbitrary policy SQL is out of scope.
  • The admin API lands last (V02-16..V02-18), after internal services are stable. No GUI is in the queue.

Compatibility

v0.1 HTTP API behaviour is unchanged by the v0.2 plan: existing auth and data routes keep their contracts, v0.1 migrations remain forward-only and immutable, and startup runtime-role checks keep their fail-closed semantics.
